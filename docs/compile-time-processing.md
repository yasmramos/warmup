# Compile-Time Processing

This document explains how the Warmup annotation processor generates zero-overhead factories at compile-time.

## Overview

The `WarmupProcessor` is a JSR 269 annotation processor that:

1. Scans for classes annotated with `@Bean`
2. Analyzes constructors and `@Inject` annotations
3. Generates factory classes implementing `CompiledFactory<T>`
4. Creates a registrar aggregating all factories
5. Registers the registrar via ServiceLoader (for compile-time factory discovery)

**Note:** The JIT compiler (`AsmJITCompiler`) used for runtime bytecode generation is now instantiated directly from `warmup-core` and no longer uses ServiceLoader discovery. Only the `FactoryRegistrar` mechanism for compile-time generated factories continues to use ServiceLoader.

## Processor Configuration

### Maven Setup

```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.apache.maven.plugins</groupId>
            <artifactId>maven-compiler-plugin</artifactId>
            <version>3.11.0</version>
            <configuration>
                <source>17</source>
                <target>17</target>
                <annotationProcessorPaths>
                    <path>
                        <groupId>com.warmup</groupId>
                        <artifactId>warmup-processor</artifactId>
                        <version>1.0.0-SNAPSHOT</version>
                    </path>
                    <!-- Avaje Inject generator if using both frameworks -->
                    <path>
                        <groupId>io.avaje</groupId>
                        <artifactId>avaje-inject-generator</artifactId>
                        <version>9.0</version>
                    </path>
                    <!-- JMH generator for benchmarks -->
                    <path>
                        <groupId>org.openjdk.jmh</groupId>
                        <artifactId>jmh-generator-annprocess</artifactId>
                        <version>1.37</version>
                    </path>
                </annotationProcessorPaths>
            </configuration>
        </plugin>
    </plugins>
</build>
```

### Supported Annotations

| Annotation | Target | Purpose |
|------------|--------|---------|
| `@Bean` | TYPE | Marks class for factory generation |
| `@Inject` | CONSTRUCTOR, FIELD | Marks injection points |

## Generated Artifacts

### 1. Factory Class (`XXX$$WarmupFactory`)

For each `@Bean` class, a factory is generated:

**Input:**
```java
package com.example;

import com.warmup.annotations.Bean;
import com.warmup.annotations.Inject;

@Bean
public class UserService {
    
    private final UserRepository repository;
    
    @Inject
    public UserService(UserRepository repository) {
        this.repository = repository;
    }
}
```

**Generated Output:**
```java
package com.example;

import com.warmup.core.jit.CompiledFactory;
import java.lang.Class;

/**
 * Auto-generated factory for {@link UserService}.
 * DO NOT MODIFY - generated by Warmup annotation processor
 */
@javax.annotation.processing.Generated("com.warmup.processor.WarmupProcessor")
public final class UserService$$WarmupFactory implements CompiledFactory<UserService> {
    
    private final CompiledFactory<UserRepository> factory0;
    
    public UserService$$WarmupFactory() {
        // Dependencies resolved at runtime
        this.factory0 = null;
    }
    
    @Override
    public UserService create(Object... dependencies) {
        UserRepository arg0 = (UserRepository) dependencies[0];
        return new UserService(arg0);
    }
    
    @Override
    public Class<UserService> getBeanType() {
        return UserService.class;
    }
    
    @Override
    public int getDependencyCount() {
        return 1;
    }
}
```

### 2. Registrar Class (`GeneratedFactoryRegistrar`)

A single registrar aggregates all factories in the module:

```java
package com.example;

import com.warmup.core.jit.FactoryRegistrar;
import com.warmup.core.jit.CompiledFactory;
import java.util.function.BiConsumer;
import javax.annotation.processing.Generated;

/**
 * Auto-generated factory registrar for this module.
 * DO NOT MODIFY - generated by Warmup annotation processor
 */
@Generated("com.warmup.processor.WarmupProcessor")
public class GeneratedFactoryRegistrar implements FactoryRegistrar {
    
    @Override
    public void registerAll(BiConsumer<String, CompiledFactory<?>> sink) {
        sink.accept("UserService", new UserService$$WarmupFactory());
        sink.accept("com.example.UserService", new UserService$$WarmupFactory());
        // Additional beans...
    }
}
```

**Key Features:**

- Registers each factory under **both** simple name and FQN for robustness
- Uses simple class names when beans are in default package
- Implements `FactoryRegistrar` interface for ServiceLoader discovery

### 3. ServiceLoader File

Creates `META-INF/services/com.warmup.core.jit.FactoryRegistrar`:

```
com.example.GeneratedFactoryRegistrar
```

This enables automatic discovery at container startup:

```java
// In HybridContainer constructor
ServiceLoader<FactoryRegistrar> loader = ServiceLoader.load(FactoryRegistrar.class);
for (FactoryRegistrar registrar : loader) {
    registrar.registerAll((name, factory) -> registerFactory(name, factory));
}
```

## Bean Naming Convention

### Default Naming

When `@Bean.value()` is empty:

```java
@Bean
public class UserService { }  // Bean name: "UserService"

@Bean
public class APIController { }  // Bean name: "APIController" (NOT "apiController")
```

**Important:** The simple class name is used **as-is**, without decapitalization. This differs from JavaBeans convention but matches the documented behavior in `Bean.java`.

### Explicit Naming

```java
@Bean("userRepo")
public class UserRepository { }  // Bean name: "userRepo"
```

### Dual Registration

For robustness, factories are registered under both names:

```java
// In GeneratedFactoryRegistrar
sink.accept("UserService", new UserService$$WarmupFactory());
sink.accept("com.example.UserService", new UserService$$WarmupFactory());
```

This ensures resolution works whether users query by simple name or FQN.

## Constructor Selection

The processor selects constructors in this order:

1. **Constructor with `@Inject`** (highest priority)
2. **Single public constructor** (if only one exists)
3. **No-arg constructor** (if no parameters needed)

### Examples

```java
// Case 1: @Inject constructor selected
@Bean
public class Service1 {
    @Inject
    public Service1(Dep dep) { }  // ← Selected
    
    public Service1() { }  // Ignored
}

// Case 2: Single public constructor selected
@Bean
public class Service2 {
    public Service2(Dep dep) { }  // ← Selected (only one)
}

// Case 3: No-arg constructor selected
@Bean
public class Service3 {
    public Service3() { }  // ← Selected (no deps needed)
    
    private Service3(Dep dep) { }  // Not public, ignored
}
```

## Default Package Handling

The processor correctly handles classes in the default (unnamed) package:

### Factory Generation

```java
// Input: com.example.MyBean (in package)
package com.example;
@Bean
public class MyBean { }

// Generated factory has package declaration
package com.example;
public final class MyBean$$WarmupFactory { ... }
```

```java
// Input: MyBean (default package)
@Bean
public class MyBean { }

// Generated factory omits package declaration
public final class MyBean$$WarmupFactory { ... }
```

### Registrar Generation

For default package beans:

```java
// Registrar references use simple names only
sink.accept("MyBean", new MyBean$$WarmupFactory());
```

### Source File Creation

```java
// With package
filer.createSourceFile("com.example.MyBean$$WarmupFactory");

// Default package (no prefix)
filer.createSourceFile("MyBean$$WarmupFactory");
```

## Multi-Round Processing

The processor handles multi-round annotation processing:

1. **Round 1**: Process `@Bean` classes, generate factories
2. **Intermediate**: Store bean info in memory
3. **Final Round**: When `roundEnv.processingOver()` is true, generate registrar

```java
@Override
public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv) {
    // Process beans
    for (Element element : roundEnv.getElementsAnnotatedWith(Bean.class)) {
        // Generate factory
        String factoryClassName = generateFactory(...);
        processedBeans.add(new BeanInfo(...));
    }
    
    // Generate registrar on final round
    if (roundEnv.processingOver() && !processingOver && !processedBeans.isEmpty()) {
        processingOver = true;
        generateFactoryRegistrar(filer);
    }
    
    return true;
}
```

## Error Handling

The processor reports errors via `Messager`:

```java
Messager messager = processingEnv.getMessager();

// Invalid @Bean target
if (element.getKind() != ElementKind.CLASS) {
    messager.printMessage(Diagnostic.Kind.ERROR, 
        "@Bean only applies to classes", element);
}

// Generation failure
try {
    generateFactory(typeElement, bean, filer);
} catch (IOException e) {
    messager.printMessage(Diagnostic.Kind.ERROR, 
        "Failed to generate factory: " + e.getMessage(), element);
}
```

## Integration with Other Processors

Warmup processor can run alongside other processors:

### Avaje Inject

Both processors can coexist. Order doesn't matter as they process different annotations.

```xml
<annotationProcessorPaths>
    <path>
        <groupId>com.warmup</groupId>
        <artifactId>warmup-processor</artifactId>
        <version>1.0.0-SNAPSHOT</version>
    </path>
    <path>
        <groupId>io.avaje</groupId>
        <artifactId>avaje-inject-generator</artifactId>
        <version>9.0</version>
    </path>
</annotationProcessorPaths>
```

### JMH Benchmarks

JMH annotation processor must be included for benchmark generation:

```xml
<path>
    <groupId>org.openjdk.jmh</groupId>
    <artifactId>jmh-generator-annprocess</artifactId>
    <version>1.37</version>
</path>
```

Without this, `META-INF/BenchmarkList` won't be generated and benchmarks won't run.

## Performance Characteristics

### Compilation Overhead

- Factory generation: ~1-5ms per bean class
- Registrar generation: ~10-50ms (once per module)
- Total overhead: Negligible for typical projects (< 500 beans)

### Runtime Benefits

- **Zero reflection** for compile-time beans
- **Direct method calls** (~10-20ns resolution time)
- **No bytecode generation** at runtime
- **Immediate availability** (no warmup delay)
